# Часть кибербезопасности и OSINT

## Назначение

Эта часть проекта реализует локальный OSINT-процесс: получение открытых данных Telegram-профилей, хранение результатов, поиск внешних цифровых следов и расчет уровня экспозиции.

## Реализованные модули

- `telegram_service.py` - сбор Telegram-профилей через API.
- `parser.py` - CLI-запуск сбора группы.
- `database.py` - SQLite, статусы проверок, экспорт и аналитика.
- `sherlock_integration.py` - поиск аккаунтов через Sherlock.
- `snoop_integration.py` - опциональный второй источник username-enrichment.
- `maigret_integration.py` - ручная глубокая проверка username через Maigret.
- `app.py` - desktop-интерфейс для оператора.

## Поток данных

1. Пользователь задает Telegram-группу или отдельный профиль.
2. Система получает открытые поля профиля.
3. Данные сохраняются в SQLite.
4. Для профилей с username запускаются проверки Sherlock/Snoop.
5. Maigret запускается вручную для выбранного профиля.
6. Найденные аккаунты сохраняются с источником и временем проверки.
7. Система рассчитывает `osint_score` и `exposure_level`.
8. Данные передаются AI/NLP-части для поиска и identity matching.

## OSINT-признаки

В оценку цифрового следа входят:

- наличие username;
- заполненность bio;
- длина и информативность bio;
- наличие аватара;
- количество Telegram-групп;
- количество найденных внешних аккаунтов;
- наличие профессионально значимых площадок.

## Ограничения

OSINT-инструменты ищут совпадения по username. Это полезный сигнал, но не доказательство личности. Поэтому проект отдельно оценивает риск ложного совпадения через AI-модуль `identity_matcher.py`.

## Безопасность эксплуатации

- API-ключи не хранятся в коде;
- Telegram session-файлы не передаются;
- база и модели работают локально;
- проект предназначен для учебного анализа открытых данных;
- результаты требуют ручной проверки.
