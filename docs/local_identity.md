# SpiderFoot и Qwen: настройка и проверка

Утверждённая тема работы: «Разработка локальной OSINT-системы для кроссплатформенного поиска и вероятностного сопоставления цифровых профилей пользователей с применением методов обработки естественного языка и машинного обучения».

## 1. Проверить существующее окружение

Из корня проекта:

```bash
python scripts/check_local_ml.py
python -m pip install -r requirements-qwen.txt
```

PyTorch и safetensors не являются самой моделью. Для Qwen отдельно нужны веса,
config.json, токенизатор и шаблон чата. Существующие веса sentence-transformers
не подходят для AutoModelForCausalLM.

PyTorch не включён в requirements-qwen.txt: сохраните уже установленную
CPU/CUDA-сборку. Если его нет, установите подходящий вариант по инструкции
https://pytorch.org/get-started/locally/ . Для CUDA 4-bit дополнительно
установите bitsandbytes; поддержка зависит от ОС, GPU и установленной версии.

## 2. Подготовить веса

Начальная конфигурация: Qwen/Qwen3-8B. Для сравнения можно выбрать
Qwen/Qwen3-14B тем же способом. Это варианты для эксперимента; преимущество
14B на сопоставлении этих профилей пока не проверено.

Первичное скачивание выполняется отдельно, с доступом к Hugging Face:

```bash
python -c "from huggingface_hub import snapshot_download; snapshot_download('Qwen/Qwen3-8B', local_dir='models/qwen3-8b')"
```

В .env:

```dotenv
QWEN_MODEL=models/qwen3-8b
QWEN_LOAD_IN_4BIT=0
```

Если полная папка уже есть, укажите её абсолютный путь. Можно указать и ID
модели, если она полностью скачана в кэш Hugging Face. Проверка использует
local_files_only=True, use_safetensors=True, trust_remote_code=False и не
скачивает недостающие файлы. Transformers должен быть версии не ниже 4.56.

Память: у неквантованных 8B весов в BF16 примерно 16 ГБ только на параметры,
у 14B — примерно 30 ГБ. Контекст и выполнение требуют дополнительной памяти.
Файлы safetensors не означают, что веса уже квантованы в 4-bit.
Это отличается от GGUF Q4 в Ollama. accelerate распределяет веса по доступной
памяти; при переносе части работы на CPU выполнение может быть медленным.

QWEN_LOAD_IN_4BIT=1 включает BitsAndBytes NF4 на CUDA. Совместимость и расход
памяти нужно проверить на конкретном ПК. Не включайте этот режим для CPU.

## 3. SpiderFoot в отдельном окружении

Не добавляйте requirements SpiderFoot в окружение курсовой: диапазоны
зависимостей, включая networkx, различаются.

```bash
git clone https://github.com/smicallef/spiderfoot.git
cd spiderfoot
python -m venv .venv
```

Windows:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Linux/macOS:

```bash
.venv/bin/python -m pip install -r requirements.txt
```

SpiderFoot может потребовать отдельную совместимую версию Python. После
установки проверьте sf.py --help в этом окружении.

Пример .env для Windows, подставьте реальные пути:

```dotenv
SPIDERFOOT_DIR=D:/tools/spiderfoot
SPIDERFOOT_PYTHON=D:/tools/spiderfoot/.venv/Scripts/python.exe
```

Вызов ограничен модулем sfp_accounts, а stdout — событиями внешних аккаунтов.
Парсер учитывает, что CLI заменяет коды типов человекочитаемыми названиями,
а URL выдаёт внутри текстового поля data. Читается только stdout текущего
процесса; чужие отчёты на диске не используются. Таймаут или повреждённый JSON
считается ошибкой, прежние находки в БД при такой ошибке не заменяются.
В установленном upstream sfp_accounts отключена проверка TLS (verify=False);
это ограничение источника нужно учитывать при оценке найденных кандидатов.

## 4. Запустить проверку

Откройте карточку существующего Telegram-профиля в приложении. Сначала запустите
SpiderFoot, затем Qwen. Внешний поиск передаёт ник сайтам, а получение публичных
метаданных обращается к API площадки. Сам Qwen выполняется локально.

CLI из корня проекта (замените ID и ник на профиль из своей базы):

```bash
python scripts/review_identity.py --user-id 12345 --username example_user --spiderfoot
python scripts/review_identity.py --user-id 12345 --qwen
```

По умолчанию обрабатывается до 20 уникальных URL. Если их больше, CLI сообщает
об этом до запуска; для полной проверки задайте --limit (максимум 500).
Ошибки сети, загрузки модели и JSON выводятся как ошибки, не как несовпадение.

## 5. Что умеет первая версия

- SpiderFoot сохраняет source=spiderfoot в существующей таблице social_accounts.
  Он запускается вручную, автоматической постановки в очередь пока нет.
- Реальные username, name, bio и blog автоматически извлекаются только из
  публичного GitHub API для пользовательских профилей. Репозитории и организации
  не рассматриваются как профили человека. Другие площадки получают
  insufficient_evidence; дополнительные адаптеры ещё нужны.
- Qwen не получает название сайта, поисковый ник и старый рейтинг как признаки
  личности. Выход проверяется по схеме и точным цитатам во входных полях.
  Доступа к инструментам у модели нет.
- Совпадение ника само по себе не допускает положительного вывода. Число
  поддерживающих признаков не превращается автоматически в вероятность.
- Дубли URL разных сборщиков анализируются один раз в рамках проверки.
  Сами находки источников остаются отдельными строками в текущей схеме БД.
- Разбор сохраняется в qwen_identity_reviews с моделью, временем и снимком
  фактических внешних данных. Кэш действует сутки и инвалидируется при изменении
  Telegram-полей, времени обнаружения аккаунта, модели или версии промпта.
- Существующий IdentityMatcher больше не принимает подставленный сборщиком ник
  за реально наблюдаемый username и не ищет совпадения bio в названии сайта.
  Старые joblib-модели несовместимы с новой семантикой признаков и отключаются
  до переобучения с feature_schema_version=2.
- Карточка и Markdown-отчёт показывают разбор Qwen; ручные подтверждения не
  меняются. Работа с изображениями и распознавание лиц не добавляются.

Кэш содержит открытые данные профилей и хранится только в локальной БД.
Веса и БД исключены из git.

## 6. Эксперимент для курсовой

Для утверждённой темы одного заключения LLM недостаточно. Нужны вручную
проверенные пары, в том числе отрицательные пары с одинаковыми никами,
неполные профили и противоречия. Делите train/validation/test по людям.
Сравните точное совпадение ника, правила, ML и добавление текстовых признаков
Qwen. Порог и калибровку выбирайте на validation, финальные precision/recall/F1
и Brier score считайте на независимом test. Пока это не сделано, числовой
рейтинг правил и заключение Qwen не называются проверенной вероятностью.

Текущий train_identity_matcher.py по-прежнему нуждается в переработке разбиения
и оценки; эта интеграция добавляет только версию схемы признаков.

## Повторная проверка формата ответа Qwen

В версии промпта 2 JSON-схема задаётся также ограничением допустимых токенов
через lm-format-enforcer. Модель не может свободно добавлять поля или менять
форму объекта. Проверка точных цитат и отказ при обрезанном ответе сохранены.
Формат JSON сам по себе не подтверждает правильность вывода о человеке.

После обновления кода установите обновлённый requirements-qwen.txt.
Повторно скачивать веса не требуется. В активированном окружении:

```powershell
$env:QWEN_MODEL = 'D:\kursa4_osint\models\qwen3-8b'
$env:QWEN_LOAD_IN_4BIT = '1'
python scripts/smoke_qwen.py --debug-raw
```

Скрипт использует только два вымышленных профиля и не открывает БД.
При ошибке валидации --debug-raw показывает исходный ответ модели.
Подготовка индекса токенизатора происходит один раз при загрузке процесса.
Предупреждения от старых torch_dtype и sampling-параметров устранены заменой
на dtype и отдельную конфигурацию greedy-генерации.
