# Курсовая работа

## Тема

Разработка локальной OSINT-системы для сбора открытых данных о пользователях Telegram, поиска внешних цифровых следов и интеллектуального анализа профилей с применением NLP/AI.

## Цель работы

Цель проекта - разработать прикладную систему, которая помогает собирать открытые сведения о Telegram-профилях, сохранять их в локальную базу данных, обогащать найденными внешними аккаунтами и выполнять аналитический поиск по собранному набору данных.

## Задачи

1. Реализовать сбор открытых профилей Telegram через API.
2. Организовать хранение профилей, групп, статусов проверок и найденных внешних аккаунтов в SQLite.
3. Интегрировать инструменты username-enrichment: Sherlock, опционально Snoop и ручную углубленную проверку Maigret.
4. Рассчитать показатели цифрового следа: `osint_score` и `exposure_level`.
5. Реализовать NLP-поиск по профилям и гибридное ранжирование.
6. Добавить AI-классификацию профессиональной направленности профиля.
7. Реализовать модель проверки, может ли найденный внешний аккаунт принадлежать тому же человеку.
8. Подготовить интерфейс, экспорт отчетов и демонстрационный сценарий.

## Архитектура решения

Проект разделен на четыре слоя:

| Слой | Назначение | Основные файлы |
|---|---|---|
| Сбор данных | Получение открытых Telegram-профилей и realtime-проверка отдельных пользователей | `telegram_service.py`, `parser.py` |
| Хранение и отчеты | SQLite-схема, связи пользователь-группа, статусы проверок, экспорт CSV/Markdown | `database.py`, `exp_csv.py`, `con_db.py` |
| OSINT-обогащение | Поиск внешних аккаунтов по username через Sherlock/Snoop/Maigret | `sherlock_integration.py`, `snoop_integration.py`, `maigret_integration.py` |
| AI/NLP-анализ | Семантический поиск, гибридное ранжирование, классификация и identity matching | `nlp_search_engine.py`, `ai_classifier.py`, `identity_matcher.py` |

## Поток данных

1. Пользователь запускает приложение и задает Telegram-группу или отдельный профиль.
2. Сервис на основе Telethon получает открытые поля профиля: имя, username, bio/about, фото и связь с группой.
3. Данные сохраняются в SQLite.
4. Для профилей с username создаются задачи проверки Sherlock/Snoop, а Maigret запускается вручную из карточки профиля для углубленной проверки.
5. Найденные внешние аккаунты сохраняются вместе с источником и временем проверки.
6. Система пересчитывает OSINT-признаки, общий балл цифрового следа и уровень экспозиции.
7. NLP-модуль строит поисковую выдачу по смыслу запроса и может усиливать ранжирование OSINT-сигналами.
8. AI-модули добавляют профессиональный класс профиля и оценку принадлежности внешнего аккаунта тому же человеку.
9. Интерфейс показывает аналитику, карточки профилей, результаты поиска и выгрузки.

## Реализованные функции

### OSINT-сбор

- сбор профилей из Telegram-групп;
- проверка отдельного профиля по `@username`, `t.me/...` или user id;
- обработка ограничений Telegram, включая `FloodWaitError`;
- сохранение статусов проверок: `pending`, `done`, `error`, `skipped`;
- экспорт baseline/enriched dataset, OSINT CSV и Markdown-сводок.

### Обогащение цифрового следа

- запуск Sherlock для поиска внешних аккаунтов по username;
- опциональный запуск Snoop при наличии локальной установки;
- ручной запуск Maigret для расширенной проверки username;
- хранение найденных аккаунтов с признаком источника;
- расчет `osint_score` на основе username, bio, фото, групп, внешних аккаунтов и других признаков.

### AI/NLP

- семантический поиск через `sentence-transformers`;
- fallback на лексический поиск при недоступности embedding-модели;
- гибридное ранжирование по формуле:

```text
hybrid_score = semantic_score * 0.70 + osint_boost * 0.20 + match_bonus * 0.10
```

- классификация профилей по направлениям: `backend`, `frontend`, `designer`, `devops`, `analyst_security`, `other`;
- обучение классификатора LogisticRegression поверх эмбеддингов;
- identity matching для оценки найденных внешних аккаунтов.

## Интерфейсы

Основной интерфейс - Tkinter-приложение `app.py`. Оно подходит для локальной демонстрации сбора, карточек профилей, OSINT-аналитики и поиска.

Дополнительно подготовлен Streamlit-интерфейс `streamlit_app.py`, который удобен для демонстрации аналитики и интерактивного просмотра результатов через браузер.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

Также выполнена синтаксическая проверка основных Python-файлов через `compile(...)` без записи `pyc`-кэша.

## Ограничения и безопасность

- Реальные Telegram API ID/API hash и сессионные файлы не должны храниться в репозитории.
- В проекте оставлен только `.env.example`; локальный `.env` создается пользователем самостоятельно.
- Внешние результаты Sherlock/Snoop/Maigret требуют аккуратной интерпретации: совпадение username не доказывает принадлежность аккаунта тому же человеку.
- Система предназначена для учебного анализа открытых данных и не должна использоваться для нарушения приватности или правил платформ.

## Вывод

В ходе работы создана локальная OSINT-система полного цикла: от сбора открытых Telegram-профилей до хранения, обогащения, поиска, классификации и формирования отчетов. Практическая часть включает рабочий интерфейс, базу данных, набор экспортов, ML/NLP-модули и демонстрационный сценарий. Проект готов к защите при условии запуска на локальной машине с установленными зависимостями и корректно заданными Telegram-ключами для live-сбора.
